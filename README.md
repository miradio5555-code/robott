# ULA Factory — учёт заказов из Китая

Система учёта заказов для закупок в Китае. Работает на GitHub Pages, данные хранятся в Supabase.
Языки интерфейса: русский, English, 中文.

## Как это работает

- **Ссылка для регистрации байеров**, без ограничения числа, подходит для групп: `https://miradio5555-code.github.io/robott/#/join`.
- **Личное приглашение** работает для одного человека 14 дней: «Байеры» → «Создать приглашение».
- **Байер регистрируется сам**: кнопка «Зарегистрироваться» на странице входа (имя, телефон, почта, пароль)
  или «Войти через Google». Ссылки-приглашения тоже работают. Байер сразу получает свой отдельный кабинет:
  свои заказы, клиенты, адрес склада. Другие байеры его данные не видят.
- **Админ** может открыть любой кабинет и посмотреть его (только чтение, менять нельзя),
  а также заблокировать байера.
- Номера заказов выдаются автоматически: `CN-000001`, `CN-000002`… Буквы меняются в настройках кабинета.
- Адрес склада в Китае вписывается в кабинете (блок «Склад в Китае» → «Изменить»)
  и копируется одной кнопкой вместе с контактами — для отправки клиенту.
- Для каждого заказа есть ссылка вида `https://miradio5555-code.github.io/robott/?order=токен`.
- Во вкладке ссылки байер может отключить ссылку или заменить её новой. Старая ссылка сразу перестаёт открывать заказ.
- По ссылке клиент видит только свой заказ и заполняет **данные для доставки**:
  ФИО, телефон, Telegram (необязательно), город, адрес или пункт выдачи.
- Если данные уже есть, клиент видит их и может нажать «Изменить».
  После статуса «Выдан клиенту» или «Отменён» менять нельзя.
- В кабинете:
  - в карточке заказа — блок «Данные клиента для доставки»;
  - на карточке в списке — город клиента или красная пометка «Нет адреса»;
  - вкладка «Клиенты» — поиск по имени и телефону, кнопка «Выгрузить в Excel (CSV)».
- Клиенту не показываются: поставщик, ссылка 1688, цена в ¥, курс и внутренний комментарий.

## Расчёты и валюты

В каждом заказе байер сам выбирает **валюту закупки** (в чём платит поставщику, например CNY или USD)
и **валюту для клиента** (в чём выставляет клиенту, например KGS, RUB, KZT). Валюты по умолчанию
задаются в настройках кабинета.

Валюта закупки — только **USD или CNY**.

- Товар (в валюте закупки) = количество × цена за единицу
- Товар в валюте клиента = товар × курс (сколько единиц валюты клиента за 1 единицу валюты закупки)
- Доставка (в валюте доставки, обычно USD) = вес × тариф за 1 кг (сумму можно вписать вручную)
- Доставка в валюте клиента = доставка × курс доставки
- **Себестоимость** = товар в валюте клиента + доставка в валюте клиента
- **Цена для клиента** — вписывает байер (или наценку в %, тогда цена посчитается сама)
- **Прибыль** = цена для клиента − себестоимость
- **Остаток** = цена для клиента − оплачено (если цена не указана — считается от себестоимости)

Валюта доставки и тариф за кг по умолчанию задаются в настройках кабинета.

Если валюты одинаковые, курс равен 1. В сводке на главной суммы считаются без отменённых заказов,
каждая валюта отдельно. Клиент по ссылке видит **только**: «К оплате», «Оплачено», «Осталось оплатить» — в своей валюте.
Цену у поставщика, доставку, курсы, тариф за кг, себестоимость, прибыль и WeChat поставщика клиент не видит.

## Умный помощник 💡

Бесплатный, работает без ИИ. На вкладке «Заказы» сам находит, что требует внимания:
заказы без цены для клиента, без адреса доставки, без курса, в убытке, «застрявшие» (10+ дней без изменений),
долги клиентов по прибывшим заказам, нет адреса склада; показывает прибыль за месяц.
Кнопка «Показать» отфильтрует такие заказы, «Открыть» — откроет заказ.
У админа во вкладке «Байеры» свой помощник: новые байеры, кто зарегистрировался и не работает, заблокированные.

## 🤖 ИИ-помощник администратора (Google Gemini, бесплатный тариф)

Во вкладке «Байеры» у админа есть чат с ИИ: вопросы о байерах, заказах, прибыли, а также помощь с текстами
(письма поставщикам на китайском, переводы). Работает через функцию Supabase `supabase/functions/ai-assistant`.

- Функция проверяет, что спрашивает админ (`is_admin()`), байеры её вызвать не могут.
- В Gemini отправляются только общие цифры по кабинетам; имена, телефоны и адреса клиентов не отправляются.
- Ключ хранится в Supabase → Edge Functions → Secrets под именем `GEMINI_API_KEY` (в коде сайта ключа нет).
- Бесплатный ключ: https://aistudio.google.com/apikey . На бесплатном тарифе Google может использовать вопросы
  для улучшения своих моделей.

Меню «☰ Раздел ▾» → «Настройки»: тема (авто / светлая / тёмная), язык, профиль (имя, телефон, новый пароль),

## 📦 Партии (несколько заказов одним карго)

Раздел **«Партии»**. Как пользоваться:

1. «Новая партия» → название, карго, дата отправки, валюта доставки.
2. Укажите **тариф за 1 кг** или **сумму по счёту карго** (если указана сумма, тариф не используется).
   **Вес партии по весам карго** (необязательно): если пусто, берётся сумма весов заказов.
3. «Добавить заказы»: выберите заказы (не в другой партии, не отменённые и не выданные).
4. Внизу сразу видно, сколько получит каждый заказ. «Сохранить и разделить».

Как делится: стоимость партии (сумма по счёту или тариф × вес партии) распределяется между заказами **пропорционально их весу**
(`weight_kg` в заказе). Последний заказ получает остаток, поэтому сумма сходится до копейки. Каждому заказу записываются
доставка, тариф и валюта доставки, а курс берётся из «Моих курсов» (если для пары валют курса нет, остаётся прежний курс заказа и
показывается предупреждение). Себестоимость и прибыль заказа пересчитываются сами.

- Деление выполняет база (функция `shipment_recalc`, её проверяют автотесты); сайт показывает тот же расчёт заранее, пока вы вводите данные.
- Вес или статус заказа из партии поменяли, заказ удалили или отменили: партия делится заново автоматически.
- **Статус всей партии** меняется одной кнопкой, после этого можно по очереди «Сообщить клиентам».
- Заказ без веса доли не получает. Заказ, убранный из партии, сохраняет прежнюю стоимость доставки: поправьте её в заказе.
- В заказе, который лежит в партии, ручная правка доставки перезапишется при следующем пересчёте (в форме заказа есть предупреждение).

## 📊 Отчёт по прибыли

Раздел **«Отчёт»**: период (этот месяц / 3 / 12 месяцев / всё время), сверху — прибыль, выручка, себестоимость, сколько уже оплатили клиенты и сколько ещё должны.
Ниже три вида: **по месяцам** (с изменением к прошлому месяцу ▲▼), **по клиентам** (с долей в общей прибыли), **по товарам** (одинаковые названия объединяются).

- Считаются заказы с ценой для клиента, без отменённых. Месяц — по дате заказа. Прибыль = цена для клиента − себестоимость;
  наценка = прибыль / себестоимость (как в форме заказа). Сколько заказов без цены не вошло — написано внизу.
- Деньги в разных валютах не складываются: если есть несколько валют, появляется переключатель.
- Кнопка **«Выгрузить в Excel (CSV)»** сохраняет текущий вид и период (русские заголовки, число с десятичной запятой по языку интерфейса).
- Отчёт считается в браузере из уже загруженных заказов, ничего не отправляется.

## 💸 Долги и напоминания

Раздел **«Долги»** (в меню; туда же ведёт карточка «Долг клиентов» на главной).

- Долг = остаток по заказу (к оплате − оплачено) там, где указана **цена для клиента**. Заказы без цены и отменённые не считаются
  (иначе «к оплате» равнялось бы себестоимости, а её клиенту называть нельзя). Сколько таких заказов не вошло — написано внизу страницы.
- Заказы одного клиента объединяются (по телефону, иначе по имени). Суммы считаются отдельно по каждой валюте.
- **Просрочено** — 7 и больше дней с заказа или с последней оплаты. Выше в списке те, у кого товар уже прибыл или выдан, потом самые давние.
  Фильтр «Просроченные». Красная цифра у пункта меню «Долги» показывает, сколько клиентов просрочили оплату.
- Кнопка **«Напомнить об оплате»** открывает готовый текст (RU / EN / 中文): один заказ — с суммами и ссылкой на заказ, несколько — списком с итогом.
  Если долг старше 14 дней, добавляется строгая фраза. Дальше «WhatsApp», «Telegram» или «Копировать».
- Сайт сам ничего не отправляет. Когда нажали «WhatsApp», «Telegram» или «Копировать», у клиента появляется отметка «Напоминали: сегодня»
  (отметка хранится в этом браузере, не в базе).

## 🧮 Расчёт цены для клиента

Раздел **«Расчёт цены»** в меню. Порядок:

1. (по желанию) название товара и ссылка на него, например с 1688;
2. валюты (закупка USD/CNY и валюта клиента), количество, цена за 1 шт и **курс**;
3. вес (за всё или за 1 шт), валюта доставки, тариф за 1 кг, курс доставки;
4. наценка в % и округление цены вверх (до 10 / 50 / 100).

Считается так же, как в заказе: товар × курс + вес × тариф × курс доставки = себестоимость; цена для клиента = себестоимость × (1 + наценка).
Внизу готовый **ответ клиенту** (RU / EN / 中文) с кнопками «WhatsApp» и «Копировать». В нём только цена для клиента,
себестоимость и прибыль клиент не видит. Кнопка **«Создать заказ из расчёта»** открывает форму заказа, уже заполненную.

**Курсы.** Поля курса заполняются вашими сохранёнными курсами. Нет своего курса — подставляется рыночный (open.er-api.com) с пометкой.
Кнопка «Запомнить курс» сохраняет курс в кабинете (`workspaces.custom_rates`): он подставляется и в новые заказы.
Список сохранённых курсов, с возможностью удалить, внизу раздела («Мои курсы»). Наценку, округление и способ указания веса телефон запоминает.

## Безопасность

- Ключ `anon` / `publishable` в `config.js` публичный, это нормально: доступ к данным закрыт правилами Row Level Security.
- Ключ `secret` / `service_role` вставлять в проект **нельзя**.
- Роли хранятся в таблице `profiles` (`admin` или `buyer`). Таблица `admins` больше не используется,
  её записи перенесены в `profiles`.
- Регистрация в Supabase должна быть **включена** (Authentication → Sign In / Providers → **Allow new users to sign up**).
  Каждый, кто зарегистрировался, получает **свой пустой кабинет** и не видит чужих данных.
  Лишних людей админ блокирует в разделе «Байеры».
- Supabase → Authentication → URL Configuration → **Site URL**: адрес сайта
  (`https://miradio5555-code.github.io/robott/`), чтобы ссылка из письма-подтверждения вела на сайт.
- Изоляция байеров проверяется самой базой (Row Level Security), а не только скрытием кнопок:
  даже прямой запрос к базе не вернёт и не изменит данные чужого кабинета.
- Рекомендуется добавить в пользовательское соглашение строку о том, что администратор платформы
  имеет доступ к данным для поддержки и безопасности (требование законов о персональных данных).
- Фото лежат в папке с непредсказуемыми именами. Загружать и удалять их может только байер своего кабинета.
- Перед изменениями в SQL запускайте проверки: `bash tests/run_db_tests.sh` (подробно в [DATABASE.md](DATABASE.md)).

### Как защищены данные клиентов

- Посетитель без входа **не может** читать или менять таблицу `clients` напрямую.
- Клиент работает только через две функции базы, и обе требуют секретный токен заказа из ссылки
  (32 случайных символа — подобрать невозможно):
  - `get_client_order(токен)` — показывает заказ и данные клиента, привязанного **именно к этому заказу**;
  - `save_client_info(токен, …)` — меняет **только** клиента этого заказа (или создаёт его, если ещё нет).
- Поиска клиентов по телефону для посетителей нет: нельзя ввести чужой номер и увидеть чужие данные.
- Формат телефона, длина полей и прочее проверяются дважды: на странице и в самой базе.
- Если ссылка попала к чужому человеку, он увидит этот один заказ. Ссылку отправляйте только самому клиенту.

## Если что-то не работает

- Белый экран «Нужно заполнить config.js» — проверьте адрес и ключ в `config.js`.
- «Неверная почта или пароль» — проверьте пользователя в Supabase → Authentication → Users.
- «У этого аккаунта нет доступа» — кабинет не создался при регистрации. Попросите байера выйти и войти снова:
  сайт создаст кабинет сам. Если не помогло, напишите в поддержку.
- «Аккаунт заблокирован» — админ заблокировал байера во вкладке «Байеры».
- Байер зарегистрировался, но не может войти — он не подтвердил почту (письмо от Supabase).
- Ссылка клиента показывает белый экран — откройте её в Chrome или Safari, а не во встроенном браузере мессенджера.
- При запуске SQL появилось «СТОП: файл N старше…» — этот файл уже не нужен, база не изменилась (см. DATABASE.md).
- Сайт не открывается из Китая — попробуйте VPN. GitHub Pages и Supabase иногда работают нестабильно.

## 📥 Заявки по ссылке

На странице «Заказы» кнопка **«Ссылка для заявок»**: создать ссылку, скопировать, отправить клиенту в мессенджер.
Клиент без регистрации вписывает ссылку на товар (или название), количество, имя и телефон. В кабинете появляется заказ

- Защита: проверка данных, не больше 5 заявок в час с одного телефона, 20 в час и 100 в сутки на кабинет, скрытое поле-ловушка для ботов.

## 👥 Помощник в кабинете

Меню → **«Команда»** → «Пригласить помощника». Ссылка копируется — отправьте её помощнику (кнопка WhatsApp тоже есть).
Помощник открывает ссылку, регистрируется (или входит) под своим паролем — и попадает в ваш кабинет. Ссылка работает 3 дня и один раз; помощников до 5.

| Помощник может | Помощник не может |
|---|---|
| заказы, клиенты, партии, поставщики, фото, «Сообщить клиенту», долги, расчёт цены, поддержка | удалять заказы, клиентов, партии, поставщиков; менять настройки, «Мои курсы», ссылку для заявок; звать и убирать помощников |

- Запреты на удаление и настройки проверяет **база** (их проверяют автотесты).
- Отчёт о прибыли, прибыль в заказах и итоги прибыли на сайте скрыты. Это скрытие на сайте: данные заказа (цены закупки) помощник технически получает. Давайте доступ тем, кому доверяете.
- Человек с собственными заказами или клиентами не может вступить в чужую команду (чтобы не потерять свои данные). Пустой кабинет, созданный при регистрации, удаляется.
- «Убрать» отключает помощника сразу; ему создаётся новый пустой кабинет, чтобы он мог войти.

## 📊 Аналитика и Excel

- Меню → **«Аналитика»** (видна владельцу): период (месяц, 3 месяца, год, всё время) и валюта. Цифры сравниваются с предыдущим таким же периодом (▲▼).
  Нажмите на столбец графика, чтобы увидеть цифры месяца. Кнопка **«Все заказы в Excel»** выгружает заказы за период.

### Цель на месяц и «Требует внимания»
- В «Аналитике» карточка **«Цель на месяц»**: впишите, сколько хотите заработать (отдельно для каждой валюты) — появится полоска прогресса, «осталось N дней» и сколько нужно зарабатывать в день. Менять цель может только владелец.
- Блок **«Требует внимания»**: заказы без цены, долги старше недели, заказы в убыток, заказы без движения 10+ дней. Нажатие на строку открывает заказ.
