# База данных ULA Factory: как обслуживать

База — Supabase (Postgres). Всё её устройство описано в SQL-файлах в корне проекта.
Номер файла = его версия: `supabase_schema.sql` — это 0, `migration_07_…` — это 7 и так далее.

## Какие файлы уже запущены

В базе есть таблица `schema_migrations`. Каждый файл в конце сам ставит в ней отметку о себе.

Посмотреть: Supabase → SQL Editor → New query →

```sql
select version, name, applied_at from public.schema_migrations order by version;
```

На 25.10.2026 в рабочей базе запущены файлы **0–23**. Файл 24 (лимит фото тетради) запускается перед выкладкой функции photo-orders: проверьте командой выше, что он отмечен.

## Главное правило: старые файлы не запускать

Несколько файлов переписывают одни и те же функции. Например, `get_client_order`, страница клиента, есть в файлах 0, 1, 4, 5, 7, 11 и 12.
Если запустить старый файл 07 после 12, клиенты перестанут видеть историю заказа.

Поэтому в начале каждого файла стоит **защита**: если в базе уже отмечен файл с бо́льшим номером, запуск
останавливается с сообщением `СТОП: файл N старше уже запущенных…`. **В базе при этом ничего не меняется.**

- Последний файл можно запускать повторно, это безопасно.
- Увидели «СТОП» — значит, этот файл уже не нужен.

## Как добавить новое изменение базы

1. Создать файл со следующим номером: `migration_25_что_делает.sql`.
2. В начало вставить защиту, а в конец — отметку. Скопировать оба блока из любого файла и поменять номер на 25.
3. Проверить на компьютере: `bash tests/run_db_tests.sh`. Должно быть «🎉 Все проверки пройдены».
4. Запустить файл в Supabase → SQL Editor → Run.
5. Если меняется функция, которая уже есть в старых файлах, копировать её **из самого нового файла**.

## Проверки перед публикацией

`bash tests/run_db_tests.sh` (нужен Docker Desktop). Скрипт создаёт временную пустую базу, применяет все файлы по порядку
и проверяет:

1. байеры не видят и не меняют чужие заказы, поставщиков и переписку с поддержкой;
2. админ видит любой кабинет, но изменить его не может;
3. без входа таблицы закрыты;
4. клиент по ссылке видит свой заказ, а цены поставщика, курсов, себестоимости, прибыли и внутренних заметок не видит;
5. отключённая или заменённая ссылка клиента больше не работает;
6. фото заказа видит только свой кабинет;
7. все файлы отмечены в `schema_migrations`;
8. старый файл не запускается поверх новых.

Рабочую базу скрипт не трогает.

## Как восстановить базу с нуля (новый проект Supabase)

1. Создать новый проект на supabase.com.
2. SQL Editor: по очереди запустить `supabase_schema.sql`, потом `migration_01…`, `migration_02…` и так далее до последнего.
3. После `supabase_schema.sql` и **до** `migration_02…` сделать себя админом:
   зарегистрироваться на сайте, затем в SQL Editor выполнить
   `insert into public.admins (user_id) select id from auth.users where email = 'ваша@почта';`
4. Authentication → Sign In / Providers: включить регистрацию по почте и, если нужно, Google.
   Authentication → URL Configuration → Site URL: адрес сайта.
5. Edge Functions: создать `ai-assistant` и `telegram-notify` (код в `supabase/functions/…`).
   В Secrets добавить `GEMINI_API_KEY` и `TELEGRAM_BOT_TOKEN`.
6. В `config.js` вписать новый Project URL и publishable-ключ.

## Резервная копия

На бесплатном тарифе Supabase не даёт скачать резервную копию. Минимум, который стоит делать раз в неделю:

- вкладка «Клиенты» → «Выгрузить в Excel (CSV)»;
- Supabase → Table Editor → таблица `orders` → Export → CSV.

Полную копию (`pg_dump`) можно сделать по строке подключения из Supabase → Connect. Попросите помощника, он подскажет команду.

## Потеряли телефон с кодом (2FA)

Если у администратора включён вход с кодом и телефон потерян, зайти в админку нельзя. Убрать код может только владелец проекта Supabase:
Supabase → Authentication → Users → ваш пользователь → в блоке «Multi-factor» удалить фактор (Delete factor). После этого вход снова будет по паролю, и 2FA можно включить заново в Настройках.
