Локальные тесты проверяют **файлы**, а не рабочую базу. «Тесты прошли» не значит «рабочая база обновлена».

## Шаг 0. Проверки на компьютере (условие для всего остального)

```bash
npm run release:check
```

Команда по очереди запускает: быстрые проверки → базу на временном Postgres → экраны в Chrome → копию сайта для iPhone.
В конце — таблица. Идти дальше можно только при итоге «ГОТОВО».

| Итог | Что значит | Что делать |
|---|---|---|
| ✅ ГОТОВО | всё выполнено и прошло | переходить к шагу 1 |
| ❌ НЕ ГОТОВО | что-то упало | исправить, повторить команду целиком |
| ⚠️ НЕ ПРОВЕРЕНО | шаг нельзя было выполнить: не запущен Docker или нет Chrome | запустить Docker Desktop (дождаться «Engine running») и повторить. Пропущенный шаг пройденным не считается: без Docker миграции **не проверены** |

Отдельные части, если нужно повторить одну:

| Команда | Что проверяет |
|---|---|
| `npm run check` | синтаксис, четыре словаря, версия во всех файлах, номера файлов базы и документы, статический анализ, память «приложения» (`sw.js`), шаблоны заказа, импорт, карточка клиента, путь заказа, WhatsApp, серверные функции |
| `npm run test:db` | все SQL-файлы на временной базе в Docker |
| `npm run smoke` | экраны сайта в настоящем Chrome с поддельной базой |
| `npm run mobile:sync` затем `npm run mobile:check` | копия сайта для приложения iPhone совпадает с сайтом |
| `npm run ios:prepare` | всё для сборки в Xcode: копия, `npx cap copy ios`, проверка |

## Шаг 1. Настоящий архив и пробное восстановление (по `BACKUP.md`)

1. Сделать архив рабочей базы (`scripts/make_backup.sh`, секреты — «Один раз добавьте секреты в GitHub»).
2. Проверить архив: раздел «Как читать результат».
3. Пробное восстановление в ОТДЕЛЬНЫЙ тестовый проект Supabase, не в рабочий. Убедиться, что заказы, клиенты и баланс открываются.
4. Не переходить дальше, пока восстановление не удалось.

## Шаг 2. Диагностика рабочей базы (только чтение)

Supabase → SQL Editor → вставить `scripts/diagnose_supabase_readonly.sql` → Run. Сохранить результат.
Строки «1 Миграции» покажут, какие файлы действительно запущены и есть ли пропуски.
Для оценки переноса клиентов (файл 56) — `scripts/preview_migration_56_readonly.sql`, тоже только чтение.

## Шаг 3. Только после шагов 0–2 и вашего явного «да»: ручной запуск недостающих файлов

Каждый файл — отдельным запросом, целиком; после каждого проверить сообщение (при «СТОП» ничего не изменено) и повторить диагностику.
Запускать только те, которых ещё нет по диагностике, строго по возрастанию номера: `… → 61 → 62 → 63 → 64 → 65 → 66 → 67 → 68 → 69 → 70 → 71`.

- Файлы 52–55 (WhatsApp) в рабочей базе уже применены — повторно не запускать.
- Файлы 45 и 46 запустить нельзя (они останавливаются): их изменения делает файл 63.
- Перед файлом 56 — оценка переноса клиентов и свежий архив.
- Файл 64 — путь заказа; 65 — обычный срок доставки кабинета; 66 — серия дней игры в профиле. Все три существующие данные не меняют и запускаются повторно без вреда.
- Файлы 67–68 — команда и задачи. Заказы и деньги не меняют. После файла 67 у всех прежних помощников роль «Помощник»; их доступ к заказам прежний. Запускаются повторно без вреда.
- Файл 69 **сужает доступ**: сотрудники с ролями без права «Все заказы кабинета» (готовые «Закупки», «Контроль качества», «Логистика») перестают видеть заказы, клиентов и деньги кабинета — только назначенные заказы в разделе «Команда». Прежние помощники («Помощник») работают как раньше. Перед запуском посмотрите в «Команда → Люди», у кого какая роль.
- Файлы 70–71 — регламенты, инциденты, календарь, сводка, аналитика. Заказы и деньги не меняют.
- Файл 72 — «Мои цели»: новые личные таблицы, существующие данные не меняет, запускается повторно без вреда.

## Шаг 4. Проверка после запуска

1. Повторить диагностику: все запущенные файлы на месте, пропусков нет.
2. По тестовой ссылке клиента (заказ без назначенной цены): сумма и остаток пустые, виден только факт оплаты; нигде нет себестоимости, поставщика, прибыли, заметок.
3. В кабинете байера: открыть заказ с адресом от клиента → «Подтвердить адрес» и «Отклонить» работают.
4. Если запущен файл 64: в карточке заказа есть блок «Путь заказа для клиента», страница клиента показывает этап.
5. Если запущен файл 66: серия дней «Всё сделано» одинакова на телефоне и компьютере.
6. Если запущены файлы 67–68: в меню есть «Команда»; помощник входит и видит свои задачи; отключённый помощник при входе видит «доступ отключён», а его заказы и комментарии на месте.
7. Если запущен файл 69: сотрудник с ролью «Закупки» входит и видит только «Команду» и назначенные ему заказы, без цен для клиента и оплат; прежний «Помощник» видит все заказы как раньше.

## Шаг 5. Публикация сайта

1. Поменять версию: `node scripts/set_version.js 20261217a` (дата и буква), затем `npm run check`.
2. Отправить ветку на GitHub, дождаться зелёных проверок во вкладке Actions, слить в `main`.
3. Через минуту открыть сайт: внизу должна появиться плашка «Вышло обновление» (или новая версия откроется сразу).
4. Для iPhone-приложения ничего пересобирать не нужно: оно открывает сайт по адресу. Пересборка в Xcode нужна, только если менялись значок, название или экран «нет интернета» — тогда `npm run ios:prepare`.
