# Импорт: серверный черновик — проект (миграция не создана)

Сейчас (после аудита) импорт работает целиком в браузере: файл → колонки → проверка каждой строки (с номером строки,
отчёт CSV) → подтверждение. До подтверждения база не меняется. До 1000 заказов сохраняются одним запросом (всё или ничего),
больше — частями с автоматическим удалением при сбое. Миграция для этого не понадобилась.

## Когда нужен серверный черновик

- файлы больше 1000 строк, где нужна настоящая атомарность без отката удалением;
- помощник загружает, а владелец подтверждает (сейчас помощник не может отменить загрузку — у него нет права удалять заказы);
- загрузка с телефона, которую нужно продолжить на компьютере.

## Модель

```
import_batches (id, workspace_id, created_by, file_name, rows_total, rows_ok, rows_skipped,
                state text check in ('draft','committed','discarded'), created_at, committed_at, committed_by)
import_rows    (batch_id → import_batches on delete cascade, line int, payload jsonb, errors text[], warnings text[])
import_commit(p_batch uuid)   -- security definer: одна транзакция insert into orders … select from import_rows where errors = '{}';
                              -- повторный вызов — ничего не делает (state = 'committed')
import_discard(p_batch uuid)
```

- RLS: черновик видят участники кабинета; подтверждает — владелец (или помощник, если владелец разрешит).
- Черновики старше 7 дней удаляются расписанием (после включения расписаний).
- Клиенту не видно ничего.

## Тесты

Атомарность (ошибка в одной строке → ни одного заказа), повторное подтверждение, чужой кабинет, помощник/владелец,
лимит строк, удаление старых черновиков.

Решение о запуске — за владельцем; визуальные изменения импорта с этой миграцией не смешивать.
